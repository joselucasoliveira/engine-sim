# Author an engine in JSON v2

Open the JSON file listed as model in the
[preset catalog](../assets/preset-catalog.json). Each preset uses one
editable file at its normal path. The catalog records its original
script and the hash of the expanded v1 reference. The desktop's model
loader, the C RuntimeSDK file and byte loaders, and the offline renderer
accept both versions. An engine loads from JSON and its WAVE resources.

The [v2 schema](../schemas/engine-config-v2.schema.json) has the identifier
urn:engine-sim:config:2. Set format_version to 2. V2 retains the v1 units
and records for fields outside the authoring forms described here. Read the
[configuration reference](engine-config.md) for load diagnostics, resource
roots and the meaning of the common fields.

## Harmonic cam profiles

In the [GM LS authoring preset](../assets/engines/atg-video-2/07_gm_ls.json),
find function-000003 in components.functions. This is the intake lobe used
by both banks. Change duration_at_50_thou_deg from 234 to 240 and load the
edited file with the normal file loader or reload it in the desktop.

~~~json
{
  "id": "function-000003",
  "kind": "harmonic_cam_lobe",
  "duration_at_50_thou_deg": 240,
  "max_lift_thou": 551,
  "gamma": 1.1,
  "steps": 256
}
~~~

Duration is measured in crankshaft degrees at 50 thou of lift. Set one
lift field, max_lift_thou for thousandths of an inch or max_lift_mm for
millimetres. The catalog uses the source script's unit when it is explicit. Gamma shapes the harmonic curve. Steps controls
sampling density. The defaults inherited from the script helper are
300 thou, gamma 1 and 100 steps. Duration is required. Keep lift above
50 thou, gamma positive and steps at least six. Preparation validates the
combination and emits one center sample, then positive and negative pairs
in the original order. The radius is the spacing between adjacent samples.
For 256 steps the profile has 511 samples.

All components reference a function by its ID. Edit the shared definition
once to change both intake cams. To give a bank an independent profile,
add a new function ID and update the relevant camshaft's lobe_profile.

## Edit points and defaults

Use ignition_timing for supplied timing points. Its filter_radius_rpm
and rpm are in revolutions per minute. Each advance_deg is in
crankshaft degrees, with the sign given in the script.

~~~json
{
  "id": "timing",
  "kind": "ignition_timing",
  "filter_radius_rpm": 1000,
  "points": [
    {"rpm": 0, "advance_deg": 12},
    {"rpm": 2000, "advance_deg": 20}
  ]
}
~~~

Use cam_samples for a measured or explicitly authored cam profile.
Set filter_radius_deg and give each angle_deg in cam degrees and
lift_m in metres. The synthetic fixture provides an example.

Use fuel_flame_speed for the original turbulence and flame-speed
table. Give each row a turbulence_speed and a flame_speed or a
flame_speed_multiplier. A direct speed is used without multiplying
by turbulence. An optional row scale defaults to 1 and multiplies
the speed or multiplier first, as in the original script.

A legacy_default_turbulence function provides the implicit
mean-piston-speed curve generated by the legacy engine. It takes an ID.
Supply a samples function with that ID to define an explicit curve.

For arbitrary points in effective v1 units, choose kind samples.
Give filter_radius, input_scale and output_scale, with both scales
equal to 1, and the x and y fields of each sample. Preserve the sample
insertion order.

## Share measured port tables

The port_flow_tables section contains the authored lift and flow_scfm
points. Set lift_unit to thou, mm or m for both the lift values and the
filter_radius. Each port_flow_28_inh2o function references a table and
may reference a port_flow_scales record. Both lift_scale and
flow_attenuation default to 1. The intake and exhaust functions for
one head can reference the same scale record. Scale records can also
be shared across heads, as in the radial presets. Edit the table to
change its shared measurements, or edit the scale to tune its linked
curves. Preparation applies the scales before the original unit and
28-inch-of-water flow conversions.

## Load and save

Use the source checkout as the resource root for catalog entries under
assets. The MIT fixture uses its own directory as the resource root.

~~~sh
"$APP" --resources "$RESOURCE_ROOT" --model "$AUTHORED_MODEL"
"$WRITER" "$AUTHORED_MODEL" "$SAVED_MODEL"
"$WRITER" --expand "$AUTHORED_MODEL" "$EXPANDED_V1"
~~~

WRITER is engine-sim-config-roundtrip. Its default v2 output retains the
authored bytes, including omitted defaults and named variants. The
--expand mode is for an effective v1 export or numerical comparison.
C++ ConfigSDK users can use engine_sim::config_json::rewrite for saving
edited source text, and engine_sim::config_json::read_model for the
effective typed model. engine_sim::config_v1::read_json and write_json
provide the version-specific v1 API. Both schemas ship with RuntimeSDK
and with the Json component of ConfigSDK.

Preparation checks the combined sample count before expanding curves.
The maximum is 1,048,576 samples per document, including explicit
points, each materialized use of a port table, and generated profiles.
Diagnostics identify the affected field and component. A rejected load
keeps the current engine. Changing a file on disk requires a new load.
Reset uses the established recipe and rechecks the file and resource
identities.
